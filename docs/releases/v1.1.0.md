# RESTOR-PC Boot Manager v1.1.0

## Overview

v1.1.0 fige le menu rEFInd à cinq entrées, ajoute un banc QEMU isolé et des outils de Golden Backup. Le tag `v1.1.0` pointe sur `1dcfffa98dd0b1ce27c0b56a27c7be47f0df81a6`.

## Boot menu

| Entry | Purpose |
| --- | --- |
| WIN CODE | Windows dédié, volume `CODE-EFI` |
| WIN VESTY | Windows dédié, volume `VESTY-EFI` |
| MEMTEST86+ | Chargeur `\EFI\TOOLS\MEMTEST\mt86plus.efi` |
| RESCUEGRID | WinPE RescueGrid, volume `RESCUE-EFI` |
| LOCKPICK | Média Lockpick complet, volume `LOCKPICK-EFI` |

L'espace restant du NVMe est volontairement non alloué.

| Volume | Rôle |
| --- | --- |
| RESTOR-BOOT | rEFInd et thème RESTOR-PC |
| CODE-EFI | Boot Windows WIN CODE |
| VESTY-EFI | Boot Windows WIN VESTY |
| RESTOR-TOOLS | Outils et RescueGrid |
| RESCUE-EFI | Boot RescueGrid |
| LOCKPICK-EFI | Média Lockpick indépendant |

## What's new

### Isolated QEMU test environment

Cinq images virtuelles sous `test\` reproduisent les volumes du menu sans disque physique.

### Finalized RESTOR-PC theme

Les icônes WIN CODE, WIN VESTY, MEMTEST86+, RESCUEGRID et LOCKPICK sont validées dans QEMU. `win_vesty.png` est un PNG 176×176 compatible rEFInd, SHA256 `CC67BBF03D668EE61DE3A4F620C3855DF4D2430F2D2BCB473658CF1CE53331F6`.

### Lockpick integration hardening

`Lockpick.iso` n'est pas dans ce dépôt. Le libellé FAT est `LOCKPICK-EF`, le nom GPT est `LOCKPICK-EFI`. L'icône versionnée n'est plus remplacée par `autorun.ico`. L'exclusion Defender reste limitée au volume Lockpick et elle est revérifiée.

### Golden Backup

`Backup-RestorBootManager.ps1` copie les ESP et les fichiers RescueGrid indispensables, puis écrit un manifeste SHA256.

### Disaster Recovery

`Restore-RestorBootManager.ps1` simule par défaut. L'écriture réelle exige `-Apply` et `-ConfirmRestore "RESTOR-PC"`, après un pré-backup.

### Safety improvements

Le NVMe est reconnu par modèle et numéro de série. Le banc QEMU refuse `PhysicalDrive`. Aucune reconstruction GPT n'est automatisée.

## Apply restore

> [!CAUTION]
> La commande suivante écrit réellement les fichiers de la sauvegarde sur la partition cible.

```powershell
.\scripts\Restore-RestorBootManager.ps1 `
  -BackupPath "C:\RESTOR-PC-BACKUP\v1.1.0-GOLDEN-..." `
  -RestorBoot `
  -Apply `
  -ConfirmRestore "RESTOR-PC"
```

`-RestorBoot` ne restaure pas les autres ESP. Si la partition n'existe plus, le script s'arrête. Il ne la recrée pas.

## Safety

- Identification du NVMe par modèle et numéro de série, pas par le seul numéro de disque.
- Dry-run par défaut.
- Pré-backup avant toute écriture `-Apply`.
- Vérification SHA256 du manifeste.
- Aucune reconstruction automatique du GPT.
- Aucun `Clear-Disk`, `Initialize-Disk`, `Remove-Partition`, `Resize-Partition`, `New-Partition`, `Format-Volume` ni `diskpart clean`.
- `bcdedit` lit la copie du BCD, pas le fichier encore monté, pour ne pas changer son timestamp.

## Third-party components

rEFInd : le binaire local `refind_x64.efi` n'est pas versionné. Voir `bootloader/README.md`.

Lockpick : `Lockpick.iso` n'est pas distribué. L'utilisateur fournit sa propre copie autorisée. Voir `Lockpick/README.md`.

## Known limitations

- QEMU vérifie le menu, les labels, le thème et le chaînage EFI.
- Les Windows complets ne démarrent pas depuis les stubs QEMU.
- RescueGrid, Lockpick et MemTest peuvent être des stubs dans le banc virtuel si les vrais payloads ne sont pas dans le dépôt.
- La reconstruction complète du partitionnement GPT n'est pas automatisée.
