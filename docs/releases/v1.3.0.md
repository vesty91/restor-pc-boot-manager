# RESTOR-PC Boot Manager v1.3.0

## Overview

Release candidate centrée sur la vérification post-restore, la reconstruction contrôlée d'un disque de remplacement vierge, le media de recovery et la provenance des fichiers critiques. Le menu rEFInd et les assets de thème restent inchangés par rapport à v1.2.0.

## Backup integrity

Deux gates d'intégrité Golden avant copie Restore. Snapshot du manifeste validé ; comparaison gate #1 / #2. Format Golden peut rester 1.1.0.

## Restore verification

Après chaque copie Golden → partition, SHA256 destination vs manifeste. `RESTORE-RESULT.json` (`VALID` / `FAILED`). Fichiers extra préservés (`/E`, pas `/MIR`). Pas de rollback automatique ; chemin PRE-RESTORE affiché.

## Full disaster recovery

`New-RestorRecoveryDisk.ps1` recrée GPT + layout RESTOR-PC sur disque RAW / GPT vide uniquement. Confirmation `REBUILD-RESTOR-PC`. Lab `Test-FullRecovery.ps1` sur VHDX 80 Gio dynamique.

## Recovery media

`Build-RestorRecoveryMedia.ps1` produit un staging sous `artifacts/recovery-media/` (Git-ignored). Pas de Golden embarqué. ISO WinPE seulement si ADK/oscdimg + source fournis.

## Test architecture

Pester offline + tags `VHD`. Safety AST pour restore, recovery et lab virtuel. Voir `docs/TEST-MATRIX.md`.

## Safety model

- Aucun `Clear-Disk` / `diskpart clean` dans recovery
- Refus disque partitionné, IsBoot, IsSystem, identité incorrecte
- Association VHDX → `Get-DiskImage | Get-Disk` avant opérations lab destructives
- Pas de destruction automatique en rollback de partitionnement

## Test results

Renseignés dans le compte rendu de la PR roadmap ; CI = validation offline.

## Release integrity

`release/RELEASE-INTEGRITY.txt` + `RELEASE-INFO.json` + `Test-ReleaseIntegrity.ps1`. Pas de génération automatique de clé de signature.

## Boot menu

WIN CODE, WIN VESTY, MEMTEST86+, RESCUEGRID, LOCKPICK.

## Compatibility

Windows PowerShell 7+, module Storage, robocopy. Laboratoires VHDX : administrateur + New-VHD ou qemu-img.

## Known limitations

- Double gate ≠ filesystem atomique
- SHA256 ≠ authentification auteur
- Post-restore sans rollback auto
- Rebuild refuse tout disque déjà partitionné
- Rebuild physique NVMe actuel non exécuté dans les labs
- VHD ≠ firmware réel
- ISO recovery dépend de WinPE/ADK
